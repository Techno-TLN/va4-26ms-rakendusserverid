# 2. kohtumine – CI/CD GitHub Actionsiga

**Eesmärk:** PR käivitab kontrolli (CI), `main`-i merge paigaldab lehe automaatselt kursuseserverisse (CD). Käsitsi `rsync`-i enam vaja ei ole.

## Ajakava (3 h)

| Aeg | Teema |
|---|---|
| 0:00–0:20 | Kordamine: kodutööd, mis on Actions (workflow → job → step), *runner* |
| 0:20–0:50 | Deploy-võti: miks eraldi võti, kuhu läheb avalik, kuhu privaatne (harjutus 1) |
| 0:50–1:30 | GitHub Secrets + deploy workflow (harjutus 2) |
| 1:30–1:40 | Paus |
| 1:40–2:20 | CI: PR-i kontroll + branch protection (harjutus 3) |
| 2:20–2:50 | Vigade otsimine: punane workflow, logid, tüüpilised vead |
| 2:50–3:00 | Kokkuvõte, kodutöö |

## Harjutus 1 – Deploy-võti

Loo **eraldi** võtmepaar, ainult GitHub Actionsi jaoks, ilma paroolita:

```bash
ssh-keygen -t ed25519 -C "github-deploy" -f ~/.ssh/tva4-26ms_deploy -N ""
```

Lisa avalik võti serveris oma kasutaja `authorized_keys` faili:

```bash
ssh-copy-id -i ~/.ssh/tva4-26ms_deploy.pub <kasutaja>@193.40.160.3.sslip.io
# Windowsis: kopeeri .pub sisu käsitsi faili ~/.ssh/authorized_keys lõppu (uuele reale)
```

Võta serveri host key (et Actions teaks, et räägib õige serveriga):

```bash
ssh-keyscan 193.40.160.3.sslip.io
```

## Harjutus 2 – Secrets ja deploy workflow

GitHub repo → **Settings → Secrets and variables → Actions → New repository secret**:

| Secret | Väärtus |
|---|---|
| `SSH_PRIVATE_KEY` | faili `~/.ssh/tva4-26ms_deploy` **kogu** sisu (ka BEGIN/END read) |
| `SSH_KNOWN_HOSTS` | `ssh-keyscan` väljund |
| `SERVER_HOST` | `193.40.160.3.sslip.io` |
| `SERVER_USER` | sinu kasutajanimi |
| `SERVER_PATH` | `/var/www/<kasutaja>` |

Kopeeri `naide/workflows/deploy.yml` → `.github/workflows/deploy.yml`, tee push ja vaata Actions vaadet.

📖 https://docs.github.com/en/actions/security-for-github-actions/security-guides/using-secrets-in-github-actions

## Harjutus 3 – CI ja branch protection

1. Kopeeri `naide/workflows/ci.yml` → `.github/workflows/ci.yml`. See kontrollib iga PR-i HTML-i.
2. **Settings → Rules → Rulesets → New branch ruleset**, sihtmärgiks `main`:
   - *Require a pull request before merging*
   - *Require status checks to pass* → vali `html-kontroll`
3. Tee meelega vigane HTML (sulgemata tag) haru peal ja ava PR. CI peab olema punane ja merge'i nupp lukus.
4. Paranda viga, CI muutub roheliseks, tee merge, deploy käivitub ja leht on serveris uuenenud.

📖 https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/about-rulesets

## Tüüpilised vead

| Sümptom | Põhjus |
|---|---|
| `Permission denied (publickey)` | Privaatvõti on secretis vigane (puuduvad read või tühik lõpus) või avalik võti pole serveris |
| `Host key verification failed` | `SSH_KNOWN_HOSTS` on tühi või vale |
| Workflow ei käivitu | Fail ei ole kaustas `.github/workflows/` või haru nimi on vale |
| Leht ei muutu | Brauseri vahemälu (Ctrl+F5) või `SERVER_PATH` on vale |

## Kodutöö

1. Tee oma lehel kolm muudatust, igaüks eraldi PR-ina. Kõik peavad läbima CI ja deploy'ma.
2. Lisa oma repo README-sse joonis (Mermaid või pilt) oma deploy teekonnast.
