# 3. kohtumine – Rakendusserver päriselt: REST API

**Eesmärk:** staatilise lehe kõrvale tuleb Node.js rakendus, mis jookseb serveris teenusena (systemd) Nginxi taga ja vastab aadressil `/api/…`. Deploy uuendab ka rakendust.

| 0:00–0:25 | REST API põhimõtted, meetodid, staatuskoodid → [SPIKKER.md](../SPIKKER.md) |

## Harjutus 1 – Lokaalselt

Kopeeri `naide/app/` oma repo kausta `app/`. Rakendusel ei ole sõltuvusi, `npm install` pole vaja.

```bash
cd app
node server.js                       # kuulab http://127.0.0.1:3000
```

Teises terminalis:

```bash
curl -i http://127.0.0.1:3000/api/health
curl http://127.0.0.1:3000/api/notes
curl -i -X POST -H "Content-Type: application/json" -d '{"text":"esimene"}' http://127.0.0.1:3000/api/notes
curl -i -X DELETE http://127.0.0.1:3000/api/notes/1
curl -i http://127.0.0.1:3000/api/olematu
```

Mis staatuskoode said? Miks?

## Harjutus 2 – Serveris teenusena

Õpetaja annab igale õpilasele **oma pordi** (3001, 3002 …).

```bash
rsync -avz ./app/ <kasutaja>@193.40.160.3.sslip.io:~/app/
ssh <kasutaja>@193.40.160.3.sslip.io
mkdir -p ~/.config/systemd/user
cp ~/app/notes.service ~/.config/systemd/user/
nano ~/.config/systemd/user/notes.service      # pane oma PORT
systemctl --user daemon-reload
systemctl --user enable --now notes
systemctl --user status notes
curl http://127.0.0.1:<sinu-port>/api/health
```

Katse: `systemctl --user stop notes` → ava brauseris `http://<kasutaja>.193.40.160.3.sslip.io/api/health`. Mis kood tuleb? (502, sest Nginx ei saa rakenduseni.) Käivita uuesti.

📖 systemd kasutajateenused: https://wiki.archlinux.org/title/Systemd/User

## Harjutus 3 – Deploy uuendab rakendust

Lisa `deploy.yml` lõppu kaks sammu (vt `naide/workflows/deploy.yml` kommenteeritud osa):

```yaml
      - name: rsync rakendus
        run: rsync -avz --delete ./app/ "${{ secrets.SERVER_USER }}@${{ secrets.SERVER_HOST }}:~/app/"
      - name: Taaskäivita rakendus
        run: ssh "${{ secrets.SERVER_USER }}@${{ secrets.SERVER_HOST }}" "systemctl --user restart notes"
      - name: Tervisekontroll
        run: curl -fsS "http://${{ secrets.SERVER_USER }}.193.40.160.3.sslip.io/api/health"
```

Viimane samm muudab deploy punaseks, kui rakendus pärast taaskäivitust ei vasta. See on lihtsaim *smoke test*.

## Kodutöö

1. Lisa staatilisele lehele JavaScript, mis kuvab `fetch('/api/notes')` abil märkmed ja võimaldab lisada uue.
2. Lisa API-sse `PATCH /api/notes/:id` ja testi seda curl'iga.
3. Mõtle: märkmed kaovad iga taaskäivitusega. Miks? Kuidas parandada?
